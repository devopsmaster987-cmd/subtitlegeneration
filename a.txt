## 0. AdSense-first principles (read before anything else)
Google rejects sites for: low-value or thin content, scaled/templated programmatic pages ("scaled content abuse"), missing or weak policy pages, poor navigation, "under construction" pages, copied content, and ads that interfere with usability. Design every decision around avoiding these.
1. Every indexable page must offer unique, useful, human-readable value. No near-duplicate pages. No keyword stuffing.
2. Content must read as written by a knowledgeable human: specific, accurate, example-driven, with real tips. No generic filler, no obvious AI boilerplate, no repeated paragraphs across pages.
3. The site needs clear authorship, an About page with real context, a working Contact page, a Privacy Policy that names Google and cookies, and a Terms page.
4. Ads must never sit inside or overlap the tool, never push content around (no layout shift), and never be disguised as content or buttons.
5. Launch small and strong: publish a limited set of excellent pages and noindex the rest until they are enriched. Quality over page count.
6. Performance and mobile usability matter: Core Web Vitals must be good with ads disabled AND with ad slots reserved.

## 1. Product goals
- User uploads a video or audio file (MP4, MOV, WEBM, MP3, WAV, M4A; up to ~500 MB, with a clear warning for large files).
- User selects the spoken language from a searchable list of all Whisper languages, or auto-detect.
- The app extracts audio and generates a timestamped transcript using Whisper running locally in the browser.
- User can review and edit every segment inline (text, start, end), split, merge and delete segments.
- Exports: SRT, VTT, TXT. Optional secondary feature: burn subtitles into the video and download MP4 (ffmpeg.wasm).
- Works offline after the first model download; model cached in IndexedDB/Cache API.

## 2. Language support (critical)

- Show a note for low-resource languages (accuracy varies) and list weak languages in the README.

## 3. Tech stack (explain any deviation)
- Next.js (latest stable, App Router, TypeScript) with `output: "export"` (fully static). Tool code is client-only. No API routes, no server actions.

- @huggingface/transformers with multilingual Whisper ONNX models: "Fast" (tiny/base) and "Accurate" (small). Prefer WebGPU, fall back to WASM. Warn about download size.

## 10. Quality bar
- Strict TypeScript; ESLint and Prettier configured. `npm run build`, `npm test`, `npm run lint` all pass. The build generates every language page and runs the content-quality gate.
- Check scripts (all run by `npm run check:all`, and the first four run in `build`):
  - `verify:keywords`: fails if a page lacks its primary keyword in H1, title, meta description, first 40 words and slug; if any keyword is assigned to more than one page; if a `secondary` keyword is not an H2/H3 or a `faq` keyword is not a visible FAQ question; if a keyword repeats more than 4 times in a page's body; if an `excluded` keyword appears anywhere outside `keywords.ts`; or if a keyword string contains a literal year. `parked` and `topic` keywords are never checked for presence.
  - `verify:wordcount`: fails if any guide has under 1,200 words of body text, the home page under 1,000, an intent landing or tool page under 700, a Tier 1 language page under 700, or a Tier 2 page under 350; also fails if more than 30% of a guide's sentences are shared with another page.
  - `verify:aeo`: fails if a tool page or guide lacks a 40-60 word answer capsule, key-facts table, six visible FAQs matching the FAQPage schema, source links, "Last updated" date, a worked example, or valid JSON-LD.
  - `verify:tokens`: fails if any bracket placeholder, "lorem ipsum", empty required config value, or empty verification tag would ship.
  - `verify:emails`: fails if any contact email other than the one in `site.ts` appears.
  - `verify:log`: fails if a formula or factual claim category (SRT/VTT formatting, language list, model sizes) has no matching entry in `/docs/verification-log.md` with source URL, method and date.
  - `verify:features`: fails if the tool page lacks any of: privacy message, language picker, editor, SRT/VTT/TXT export, accessible progress, error states.
  - `verify:links`: fails on broken internal links or orphan pages.
  - `verify:ads`: fails if ad script or ad markup appears while `ADS_ENABLED` is false, or if an ad slot appears inside the tool area, on `/studio`, or on a noindex page.
- Unit tests: timestamp formatting, SRT/VTT generate+parse, chunk stitching and overlap de-duplication, segment split/merge, language list vs model language map, content-quality gate (word counts, similarity), sitemap excludes noindex pages, AdSlot renders nothing when disabled.
- No console errors, no hydration warnings. Accessibility: labeled controls, focus states, ARIA on progress, sufficient contrast in both themes.
